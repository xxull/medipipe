# 常见错误与修复

> 按「报错原文」查。每条都给：为什么 + 怎么修。
> 拿不准就先跑 `python tools/自检.py`。

---

## 启动 / 环境

### `ModuleNotFoundError: No module named 'streamlit'`

没装依赖，或者装到了别的 Python 里。

```bash
pip install -r requirements.txt
python -m streamlit run ...
```
Windows 上常见于 `.venv` 没激活就 `streamlit`（找到的是全局的）。用 `python -m streamlit` 最稳。

### `OSError: [WinError 10061] 由于目标计算机积极拒绝，无法连接`

Ollama 没启动。翻译 / 总结 / 相似病例都会卡在这里。

```bash
ollama serve          # 或双击 Ollama 图标
python tools/自检.py   # 确认「Ollama 在线」
```

### 端口被占：`Port 8501 is already in use`

上次的窗口没关。

```powershell
Get-NetTCPConnection -LocalPort 8501 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```
或者换端口：`--server.port=8503`。

## 数据 / 检索

### `向量索引还没建：先跑 tools\建向量.py`

```bash
python tools/导入样例数据.py     # 会顺带建向量
# 或
python tools/建向量.py
```

### 搜不到东西 / 结果很少

**先确认是不是数据太少**：仓库自带 204 条病例、1000 条药品，搜不到是正常的。
看「概览」页的行数；太少就：

```bash
python tools/下载开放数据.py --openfda 20000 --medquad 0 --medquad-zip --doid 99999
python tools/导入开放数据.py --rebuild
```

### `sqlite3.OperationalError: no such table: dayi_pages`

正常。`dayi`（中文说明书）有版权，公开版不带。药品说明会自动退回 openFDA。
如果你想要中文说明书，自己跑 `python tools/爬dayi.py`（遵守 robots，仅限本地研究）。

### `sqlite3.OperationalError: no such column: gender` / `age_band`

病例库是旧脚本建的，缺列：

```bash
python tools/补性别.py
python tools/补年龄段.py
```
补完**刷新页面**即可（框架 B 的缓存按库文件戳失效，不用重启服务）。

### `sqlite3.OperationalError: no such column: product_type`

`drugs` 表是别的方式建的，列不全。重新导一遍开放数据：

```bash
python tools/导入开放数据.py --rebuild
```
（现在的代码已经对缺列做了兜底，但重导最省事。）

### 关键词检索很慢（十几秒）

没有全文索引，退回 LIKE 全表扫了：

```bash
python tools/建搜索索引.py     # 大库会跑几分钟
```

### 相似病例搜出来一堆不相关的

- 检查 `data/case_vectors.bin` 和库里的 `case_corpus` 是不是同一批（重建病例库后要重跑 `建向量.py`）
- 症状描述写具体一点（"咳嗽咳痰三天" 比 "不舒服" 好）
- 年龄段 / 性别筛得太窄也会只剩几条

## 模型 / 翻译

### 第一次点翻译要等十几秒

本地模型首次加载 + 逐条推理。之后有磁盘缓存。
想提前热一遍：

```bash
python tools/预热翻译.py 1500 300
```

### 译文里出现「勿思考」「不要思考」「/no_think」

旧版本的坑，现在用 `think=False` 并过滤垃圾词。
如果缓存在老数据里，清一次：

```bash
python tools/清翻译缓存.py          # 先看
python tools/清翻译缓存.py --apply  # 真删
```

### 数字被翻错（`0.9%` 变 `9%`）

已在 `b_翻译._numbers_ok` 里校验，数字不一致会重试；
缓存里旧的坏译文用上面的 `清翻译缓存.py` 清掉。

### 病历总结很慢 / 提示要 Key

默认走主模型（DeepSeek 等），需要 Key：在「自检」页填，或 `.env` 里
`MY_LLM_KEY=sk-...`。没 Key 时可勾「用本地模型」（20~60 秒）。

## 界面

### 页面一片空白 / 一直转圈

1. 看 `data/b_err.log`（或启动窗口）
2. 大库上第一次打开会加载向量（1~2 秒），特别大的库会更久
3. `python tools/自检.py` 看数据库和端口

### 点翻译后状态没变

已修（先算后显示）。如果还遇到，刷新一次页面，并把复现步骤发 issue。

### 表格右上角那两个小图标

Streamlit 自带的表格工具（复制 / 下载 CSV / 搜索 / 全屏），不是业务按钮。

## 生产端（框架 A）

### 画布里看不到刚写的插件

- 文件名要 `*.py`，类要继承 `BasePlugin`
- 点「↻ 重新扫描插件」或重启
- 看 `data/app.log` 里有没有加载失败的原因

### 执行一直 `pending`

前一步失败了，后面的被标成 `skipped`。点开失败那步看 `error` 字段。

### 子进程插件报 `ModuleNotFoundError`

插件在子进程里跑，只用标准库 + 项目内模块。
第三方包必须在**同一个 Python 环境**里装好。

## 网络 / GitHub

### `fatal: unable to access ... Recv failure: Connection was reset`

`github.com` 的 git 协议被中途重置（国内常见）。多试几次，或：

```bash
git config --global http.version HTTP/1.1
git push
```
还不行就开代理 / 换网络；API（api.github.com）通常不受影响。

### 打开 GitHub 仓库看不到更新

先看本地 `git status` 是不是 `ahead`；推上去了再刷新（有缓存，强刷 Ctrl+F5）。
